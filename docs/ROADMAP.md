# Roadmap

> **Срок:** среда 21.10.2026 → суббота 24.10.2026 (сдача вечером)
> Этот документ отвечает на вопрос **«КОГДА и в каком порядке»**. Что делаем — [TZ.md](./TZ.md), как — [spec/](./spec/README.md).

## Принципы

1. **Бэкенд за один день.** Весь `apps/api` пишет Claude Code участника 1 по спецификации: сначала фундамент, затем модули в параллельных сессиях.
2. **Фронтенд — вдвоём, сразу на настоящем API.** С четверга оба делают `apps/web`, моки не нужны.
3. **Дизайн до фронтенда.** Пока пишется бэкенд, дизайн обсуждается и фиксируется в `docs/design.md`, делаются базовые UI-компоненты.
4. **P0 → P1 → P2.** Сначала все P0 из ТЗ, потом P1. P2 — только если всё остальное готово.
5. **Каждый вечер** — слияние в `main`, проверка, что всё вместе работает.
6. **Один чат Claude Code — одна задача.** Короткий чат под конкретный модуль или экран работает лучше длинного.

## Роли

| | Участник 1 | Участник 2 |
|---|---|---|
| Среда | Бэкенд целиком (через Claude Code): запуск, проверка, ключи сервисов | Дизайн: `docs/design.md`, токены, базовые компоненты |
| Чт–Сб | Фронтенд | Фронтенд |

`packages/shared` (схемы, типы, коды ошибок, события сокетов) создаётся вместе с бэкендом. Фронтенд его импортирует; если нужно новое поле — сначала меняется бэкенд.

## Если не успеваем

Порядок отказа от функций (сначала убираем верхние):
1. Все P2 из ТЗ, включая прямой эфир (`LIVE-*`)
2. Highlights, обрезка фото, отметки людей
3. Реакции и ответы на сообщения в директе
4. Админ-панель урезаем до `ADMIN-1`…`ADMIN-4` (доступ, дашборд, пользователи, бан)
5. Деплой (сдаём локально)

Звонки, директ, Stories и Reels **не убираем** — это ключевые функции проекта.
