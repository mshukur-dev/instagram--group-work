# Звонки (LiveKit)

Требования: `CALL-1`…`CALL-9` в [TZ.md](../TZ.md).

## 1. Что такое LiveKit и почему он

LiveKit — сервер с открытым кодом для аудио- и видеозвонков (SFU, Selective Forwarding Unit). Каждый участник отправляет своё видео **один раз** на сервер, а сервер раздаёт его остальным. Поэтому групповые звонки не тормозят, в отличие от схемы «каждый с каждым», где при 5 участниках каждый браузер отправляет видео 4 раза.

Звонок 1 на 1 и групповой звонок для LiveKit — одно и то же: комната, где 2 или N участников. Код пишется один раз.

**Разделение ответственности:**
- **Наш API** решает, *кто* может звонить: проверяет участие в переписке, создаёт `Call` в БД, выдаёт токен доступа к комнате, рассылает сигналы через Socket.IO.
- **LiveKit** передаёт *видео и звук*. Через наш сервер медиа не проходит.

## 2. Окружения

| | Локально | Деплой |
|---|---|---|
| Сервер | Docker: `livekit/livekit-server:v1.13.10 --dev --node-ip 127.0.0.1` (без `--node-ip` браузер на Docker Desktop получает внутренний IP контейнера: звонок «соединяется», но без звука и видео) | LiveKit Cloud (бесплатный тариф Build) |
| URL | `ws://localhost:7880` | `wss://<project>.livekit.cloud` |
| Ключи | `devkey` / `secret` | из кабинета LiveKit Cloud |
| Лимиты | нет | ~5 000 минут участника в месяц (минуты считаются на каждого участника; аудио и видео тратят одинаково) |

## 3. Библиотеки

- **API:** `livekit-server-sdk` — создание токенов (`AccessToken`), проверка вебхуков (`WebhookReceiver`).
- **Web:** `livekit-client` + `@livekit/components-react` — подключение к комнате, готовые хуки и компоненты (`useTracks`, `VideoTrack`, `useIsSpeaking`…). Внешний вид сетки и кнопок делаем свой, в стиле Instagram.

## 4. Звонок 1 на 1

```
Алиса                          API                              Боб
  │ POST /conversations/:id/calls {VIDEO}                        │
  │──────────────────────────────►│ создаёт Call (RINGING),      │
  │                               │ roomName = call_<id>         │
  │◄──── { call, token, url } ────│                              │
  │ подключается к LiveKit,       │── socket: call:incoming ────►│ окно «Входящий
  │ слышит гудки                  │                              │ видеозвонок»
  │                               │◄── POST /calls/:id/join ─────│ «Принять»
  │                               │ Call → ACTIVE, answeredAt    │
  │◄──── socket: call:updated ────│──── { call, token, url } ───►│ подключается
  │◄═══════════ видео и звук напрямую через LiveKit ════════════►│
  │ POST /calls/:id/leave         │                              │
  │──────────────────────────────►│ участников < 2 → Call ENDED  │
  │◄──── socket: call:ended ──────│───── socket: call:ended ────►│
```

- **«Отклонить»** → `POST /calls/:id/decline` → `Call` = `MISSED`, обоим `call:ended`.
- **Нет ответа 30 секунд** → сервер ставит `MISSED` (таймер в `CallsService`), обоим `call:ended`.
- Пока Боб в другом звонке, новый входящий показывается как «занят» и сразу становится `MISSED`.
- Звонок 1 на 1 заканчивается, когда **любой** из двух вышел. Если звонящий положил трубку до ответа — звонок `MISSED`.
- Если Боб занят, `POST /conversations/:id/calls` всё равно отвечает `{ call, token, url }`, но `call.status = MISSED`: фронт показывает «Пользователь занят» и не подключается. Звонящему приходит `call:ended`, в чат — запись «Пропущенный звонок».
- Таймер 30 секунд живёт в памяти процесса; на случай перезапуска раз в минуту фоновая проверка закрывает «зависшие» звонки (`RINGING` старше 30 с → `MISSED`, `ACTIVE` без участников → `ENDED`).

## 5. Групповой звонок

```
1. Участник группы: POST /conversations/:id/calls → Call (ACTIVE сразу), подключается
2. Остальным участникам: socket call:incoming
   → тихое уведомление-баннер «Иван начал видеозвонок · Присоединиться»
   → в шапке чата и в списке чатов появляется плашка «Идёт звонок»
3. Каждый по желанию: POST /calls/:id/join → токен → подключается
4. Выйти и зайти снова можно в любой момент (POST /calls/:id/leave, потом снова join)
5. Вышел последний → Call ENDED, всем call:ended, плашка исчезает
```

`POST /calls/:id/decline` для группового звонка ничего не делает (204) — кнопка Decline в push просто закрывает уведомление. Максимум участников одновременно — `CALL_MAX_PARTICIPANTS` (8), дальше `409 CALL_FULL`.

Если в группе звонок уже идёт, кнопка «Позвонить» превращается в «Присоединиться». Второй звонок в той же группе начать нельзя (API вернёт 409 с id активного звонка).

## 6. Токен доступа к комнате

```ts
const at = new AccessToken(LIVEKIT_API_KEY, LIVEKIT_API_SECRET, {
  identity: user.id,
  name: user.username,
  metadata: JSON.stringify({ avatarUrl: user.avatarUrl }),
  ttl: '2h',
});
at.addGrant({ roomJoin: true, room: call.roomName, canPublish: true, canSubscribe: true });
return at.toJwt();
```

Токен выдаётся **только** участнику переписки и **только** для комнаты этого звонка.

## 7. Как сервер узнаёт, что кто-то вышел

Два источника, на случай если пользователь просто закрыл вкладку:
1. Фронт вызывает `POST /calls/:id/leave` при нажатии «Завершить».
2. **Вебхуки LiveKit** → `POST /api/calls/livekit-webhook`: события `participant_joined`, `participant_left`, `room_finished`. Подпись проверяется `WebhookReceiver` по сырому телу (LiveKit шлёт `Content-Type: application/webhook+json`, контроллер читает поток сам). Неверная подпись → 401. Обновляем `CallParticipant` и статус `Call`; `participant_connection_aborted` обрабатывается как `participant_left`. При завершении звонка API сам удаляет комнату LiveKit (`RoomServiceClient.deleteRoom`), чтобы отключить оставшихся.

Локально вебхуки настраиваются в конфиге LiveKit-сервера; если не получится — достаточно пункта 1 плюс таймаут пустой комнаты LiveKit.

## 8. Запись о звонке в чате

При завершении `Call` в переписку добавляется `Message` с `type = CALL` и `callId`. В чате отображается (интерфейс на английском): `Video call · 12 min`, `Missed audio call`, `Group call · 5 people`.

Входящий звонок при закрытой или фоновой вкладке приходит как push с кнопками **Accept / Decline** — см. [push.md](./push.md).

## 9. Интерфейс (фронтенд)

- Состояние текущего звонка — Zustand-стор `useCallStore`: `{ incoming, active, isMinimized, micEnabled, cameraEnabled }`.
- **Окно входящего звонка** (1 на 1): аватар, имя, «Принять» / «Отклонить», рингтон.
- **Экран звонка**: на весь экран; 1 на 1 — собеседник на весь экран, я в маленьком окне в углу; группа — сетка (1, 2, 2×2, 3×3); говорящий подсвечивается.
- Панель управления: микрофон, камера, переключить камеру (телефон), завершить.
- Звонок можно свернуть в плавающее окно и продолжать пользоваться приложением (P2).
- Браузер спрашивает доступ к камере и микрофону; если отказано — понятное сообщение.
